# 旗舰自动计算：线程池与请求保护

旗舰自动寻路在独立 Node.js 计算线程中执行，不在处理页面／普通接口的执行线程中同步求解。高安收尾、途经顺序、NPC 落点、入侵／屏蔽规则和每段搜索预算不变。

## 容量

| 项目 | 默认值 |
| --- | --- |
| 同时运行的计算线程 | 最多 4 个；自动保留至少一个可用逻辑 CPU，少核机器相应减少 |
| 等待队列 | 8 个独立任务 |
| 同一来源未完成的请求订阅 | 6 个，包含等待中的订阅 |
| 全池 HTTP 等待者 | 最多 48 个 |
| 同一浏览器客户端 | 同时仅一个不同参数的任务，重复订阅也有上限 |
| 入口请求体 | 16 KiB，应用层与网关均检查 |
| 应用读取请求体时限 | 5 秒 |
| 等待计算位时限 | 10 秒，含等待线程启动 |
| 单任务执行时限 | 45 秒 |
| 线程启动时限 | 5 秒 |
| 每线程 V8 old-generation 内存上限 | 384 MiB |

“4 个同时计算、8 个排队”是单个 Web 进程的容量，队列不是额外 8 个计算线程。单任务执行时限包含其全部有序点位，原算法每段 2 秒／十万状态保护仍然保留；不存在固定 30 段自动导航上限。

通过部署环境配置可调整：

- `JUMP_COMPUTE_WORKERS`：`auto` 或 1–8；默认 `auto`，按可用逻辑 CPU 数选择最多 4 个。
- `JUMP_COMPUTE_QUEUE`：0–32，默认 8。
- `JUMP_COMPUTE_SOURCE_PENDING`：1–16，默认 6。同一公网出口的多位用户会共享此来源限制，应结合实际流量调整。
- `JUMP_PUBLIC_ORIGIN`：可选的公开站点 Origin，包含协议及非默认端口，不含路径、查询、账号或密码。TLS 在上层终止时必须设为用户实际访问的站点地址，用于严格同源校验；不能用任意客户端头推测公开协议。配置错误会拒绝计算，不会静默放宽校验。

这些参数仅由服务器部署配置决定，请求体不能指定线程数、优先级或队列大小。提高并发必须复测 CPU、内存和每段搜索预算，不能只扩大队列。

## 重复请求与恶意点击

1. 前端使用同步请求引用防重，按钮进入等待状态后禁用；快速连续点击不会不断中断并重新提交计算。
2. 服务端按来源设置令牌桶：允许短时突发 16 次，按每秒 2 次补充。无效参数请求也计入，以免绕过计算入口刷解析。
3. 网关另按真实连接来源限制自动计算 POST：每秒 3 次、突发缓冲 16。取消不消耗这个 POST 配额，以便繁忙时仍能释放计算。
4. 同一来源的未完成订阅数另有限额；轮换浏览器标识不能绕过来源配额。客户端身份不是登录认证，也不单独作为防滥用边界。
5. 相同规范化参数的进行中任务共享一次计算，但 HTTP 订阅也有上限；不同用户可以独立取消自己的等待。不同舰船、技能、途经顺序、NPC／规避开关不会错误合并。
6. 不缓存已完成路线。新提交始终重新核对当前服务器快照，避免旧结果绕过入侵更新。

来源限额使用代理覆盖后的 `X-Real-IP`，不信任请求自带的 `X-Forwarded-For` 链。计算／取消网关还会覆盖 `X-Jump-Origin-Host`，配合协议头保留公开入口的主机名、协议和端口，用于同源校验。默认部署仅暴露网关，Web 服务应保持在内部网络；若另行暴露 Web 端口，必须先重新建立可信代理／真实来源边界。当前内存配额为单进程范围，未来增加多个副本时需重新设计跨副本限额。

## 取消和异常

前端为任务生成随机客户端标识和请求标识。点击取消、修改点位／规划条件、清除计算、离开页面，以及未取得响应的网络失败，都会尝试显式取消。取消接口为 `DELETE /api/navigation/jump/cancel`，标识通过请求头传递；不接受用户指定内部任务对象或线程。

服务框架可能不转发浏览器断开信号，因此不能只依赖 `request.signal`。显式取消与可用的断开信号共同工作；若浏览器已经断网／被关闭而不能送达取消，任务执行时限仍会兜底。

- 排队任务无人等待时立即移出队列。
- 运行任务最后一个等待者取消时，终止相应线程。共享任务仍有人等待时，不影响其他用户。
- 旧线程停止后才补建线程，防止取消风暴造成短时间超额启动。
- 取消先于 POST 到达时，短期保留取消标记，防止迟到请求启动孤儿任务。标记最多保留 60 秒，数量有界。
- 线程错误、崩溃、启动／执行超时会返回明确错误，释放计数并在需要时补建；不会返回伪造的不可达前缀。
- 前端收到繁忙响应后显示确认提示和短暂重试冷却，不自动反复请求，也不因限流额外刷新入侵资料。

## 快照与安全校验

计算线程以只读连接一次读取星图、舰船／站点、入侵三个缓存，基础资料校验、图构造和寻路均在计算线程中执行。每个线程按星图与舰船／站点版本缓存已验证目录及图结构。

每个新任务重新读取入侵状态与有效期。执行完成后再次核对缓存版本和错误状态；资料在计算期间更新或入侵资料自然过期时，不把旧结果发布为当前有效路线，而是要求重新计算。数据库故障不回退为安全空名单，也不访问上游同步。

## 响应

成功和合法不可达仍保持原有 `complete`／`legs`／`interruptionAt` 结构。

| 状态 | 含义 |
| --- | --- |
| 400 | 参数、舰船、点位或安全资料不满足要求 |
| 403 | 跨站提交被拒绝 |
| 408／413 | 请求体读取超时／过大 |
| 429 | 请求过频、来源配额或重复计算限制；可读取 `Retry-After` |
| 499 | 该订阅已取消，不能当作不可达 |
| 503 | 队列满、排队／执行超时、线程异常、快照更新或暂不可用 |

响应均不缓存；计算响应提供 `Server-Timing` 中的排队与线程计算耗时，用于区分等位和实际求解。响应不暴露数据库路径、来源地址或内部线程标识。

测试入口：`checks/jump-compute-pool.check.mjs`、`checks/jump-compute-worker.check.mjs`、`checks/jump-compute-api.check.mjs`，以及已有自动寻路业务检查。浏览器与并发复测证据保留在被忽略的本地运行目录。
