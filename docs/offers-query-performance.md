# 企业详情查询优化

本次只优化读取范围和容器日志，不新增业务表、不改变价格或利润公式、分页排序及同步计划。

## 查询范围

原查询的历史聚合扫描整个历史表，计数和分页又分别执行一次完整聚合。现在先按原有势力、军团、屏蔽和增效剂蓝图条件选出兑换方案：

- 历史聚合只读取所选方案的产出物品，通过已有 `(type_id,date)` 索引查询。
- 兑换材料只读取所选军团/方案，制造材料只读取所选蓝图。
- 总数统计使用完全相同的筛选和关联条件，不计算历史、利润或排名。
- 分页查询保留所有原有计算字段和排序规则；材料、订单深度、脑插套装与首页处理保持不变。

没有新增缓存，因此订单、历史或屏蔽标记更新后，下一次请求直接读取最新数据。

## 验证

新增行为测试验证新旧查询的价格、材料、排序、分页、税率、过滤和空结果一致，且执行计划不扫描无关历史。

真实数据库冻结读取快照进行完整 JSON 对照，覆盖普通方案、蓝图、脑插、全量分页、第二页、不同税率/窗口、被屏蔽军团和首页，全部相同。代表性 10 条企业详情读取从约 1.9 秒降到约 0.12 秒；全量 319 条约 0.30 秒。实际网络耗时另在部署后测量。

完整检查 133 项通过；lint 无错误，4 个既有警告未增加。

部署后真实 HTTPS 连续三次测试分别为 167、122、121 毫秒（同一企业 10 条方案，411 条总数、2 组脑插）；公开页面、企业详情、屏蔽请求及合同询价检查通过。所有同步计划和人工标记未变，容器健康。

## 日志容量

Web、同步器和 Nginx 均配置 Docker `json-file` 轮转：每文件 10 MB，最多 3 个文件，单容器约 30 MB。同步业务日志原有七天清理规则不变。

部署前保留现有容器日志、数据库和旧镜像。数据库备份暂不自动清理，避免删除仍用于回退的副本；备份保留周期后续另行确定。
