# V2.0 正式运行与清理说明

## 运行边界

业务接口只从 V2 数据库只读查询。后台由一个 V2 同步器执行写入，管理接口负责配置、排队及人工维护。不再使用旧同步接口、旧 SQLite/D1 适配层或测试模式回退。

旧 `/sync` 链接重定向到 `/sync-v2`。默认数据库和图标缓存均位于 Compose 挂载的 `/v2`，宿主运行目录为 `docker-data/v2/`。

## 正式切换校验

`node scripts/v2/cli.mjs enable` 要求：

1. SQLite 完整性与外键检查通过。
2. 物品、势力军团 LP、订单、合同、历史、榜单均有成功同步记录。
3. 核心表非空，订单和合同当前发布代的记录数与快照元数据一致。
4. 按原业务规则重算榜单，历史完成条件满足。

全部满足后写入正式就绪标记与验证记录，删除测试就绪标记。失败不授予正式就绪。Web 没有旧库自动回退，不会在错误配置下静默读另一份数据。

## 清理与恢复

清理前归档源码、环境配置及数据库一致性快照。SQLite 在运行中须通过在线备份或 `VACUUM INTO` 获得备份；不能单独复制活动 `.db` 而忽略 WAL。

先停止后台写入，再备份和校验；构建新镜像并验证；正式部署后检查所有容器、公开业务接口和管理状态。仅在新容器不再挂载旧数据库之后，将旧数据库及关联 WAL/SHM 移入私有归档。图标缓存单独迁移，不随数据库删除。

旧源码、镜像、数据库备份只用于人工恢复，不参与日常业务。恢复时先停止后台、备份当下 V2 数据，再恢复匹配的代码、配置、数据库，不把两个版本的写入器指向同一个数据库。

## 发布边界

版本标识统一为 V2.0.0。本地测试与内网验证完成后方可提交发布；远端部署需要单独确认。数据库、环境文件、日志、归档与证书不得进入 Git 或镜像。不要默认把测试环境的运行数据库迁到其他环境。
