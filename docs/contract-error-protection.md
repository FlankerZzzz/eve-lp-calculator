# 合同错误保护

- 询价输入必须是包含字符串 `text` 的 JSON 对象；null、数组、错误 JSON、空文本返回明确 400，不抛空白 500。
- 文本最多 1 MiB、单次最多 500 种输入物品，超限分别返回 413/422，不截断估价。
- 合同缓存必须为有效物品数组；损坏 JSON、非数组、无效物品结构返回 422 `INVALID_CACHE`，整份拒绝估价，不只计算剩余有效物品。
- 合法空数组或仅含支付物品的缓存返回 422 `EMPTY_CONTRACT`，支付物品不计入收到物品。
- 后台收到合法空明细数组，或无效字段、重复明细 ID、错误结构、HTTP 200 非空损坏 JSON：记录 `contract_skipped`（合同 ID、原因），整份略过，其他合同继续；原子发布时移除旧的错误合同。
- 明细 404：记录原因并略过。
- HTTP 200 无正文不同于合法空数组：保留既有完整目录复查机制。仅复查确认合同消失时移除；仍公开或复查失败时保留断点和旧快照。
- 网络、超时、503、目录不完整或页数变化：不冒充错误合同略过，整轮不替换旧快照，后续恢复重试。
- 不修改兑换量、累计买卖单深度、LP 比例规则，不新增业务表。

回归覆盖：错误输入、输入限额、损坏缓存、空缓存、错误明细不部分发布、空合同移除、其他合同继续、503 保留旧快照/断点、原有空正文复查和进程恢复。
