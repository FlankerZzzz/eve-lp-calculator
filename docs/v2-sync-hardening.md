# V2 同步与询价修复（2026-10-11）

本次不更换数据库、不新增业务表、不改 Cron 和自动开关，不删除旧库。原始订单、合同仍完整保存。

## 全量物品同步：字段级补全

同一个物品主表同步分为：读取已导入 SDE 基线 → 拉取晨曦物品目录 → 补缺失的已发布物品 ID → 补已有已发布物品的空体积字段 → 发布目录状态与结果。

- 查询 `published=1 AND sync_protected='N'` 且 `volume` 或 `packaged_volume` 为空的主表记录。
- 通过 `/universe/types/{type_id}/` 获取字段；只有有限且非负的数值可以写入。
- **0 是明确有效值**，不是未知。缺字段、null 或 404 不伪造 0；记录未补齐原因和数量。
- 只填空字段，不覆盖非空值、不变更名称、published、蓝图或来源；SDE 主记录补 ESI 字段后仍标为 SDE。
- 写入时再次检查保护标记，防止接口请求期间用户新设置的保护被绕过。
- 使用现有 `checkpoints` 保存 `volume:{type_id}` 响应；暂停/让出/失败恢复可以复用，新的手动全量轮次会重新检查仍空的字段。
- 查询中断或响应格式错误忠实报错；此前已提交的补全记录保留，任务不能虚假完成。
- INFO 日志记录开始、候选数、补齐数、复用数和仍缺失数；DEBUG 开关沿用统一接口完整数据日志。

## 单执行器、独立调度、持久化让出

- 一秒心跳中独立检查计划，不再等整个同步任务完成才检查 Cron。
- 调度游标保存在现有 `runtime_state`，跨分钟或重启最多补查过去一天；同一模块不重复入队。
- 同一时刻仍仅一个模块执行并写业务库。优先级：订单 → 合同 → 排行榜 → 物品 → LP → 历史。
- 物品、LP、历史运行时若有更高优先级任务到达，取消未完成请求，已成功数据/分页/军团或物品断点保留，当前任务回到队列。短任务完成后使用同一 run_id 恢复。
- 统一请求池限流和退避不变，历史专用较慢速率在让出时恢复为普通模块速率，恢复历史时再切回慢速率。
- 正常退出将活动任务重新排队并保留断点；过期租约后的进程启动将遗留 running 恢复为 queued。用户手动暂停仍是 paused，不与进程退出混淆。
- 对完成任务点击“运行”产生新轮次；暂停或失败点击“恢复”保留 run_id；“重新同步”始终从新轮次开始。
- 成功后清理该模块更早 run_id 的断点，保留最近一轮便于极短崩溃窗口幂等恢复；不清理仍进行中的断点。

## 订单快照稳定性

- 每页验证数组、总页数、必要字段与重复订单 ID。
- 总页数变化或重复 ID 视为分页快照不稳定，整轮重新采集，最多三轮；不是 UPSERT 或静默跳过重复。
- 持续不稳定、非法数据或请求失败不发布半份快照；原有报价、深度及原始有效订单不变。失败暂存清除，下次计划可重试。
- 只有所有页完成后才在单事务内发布报价、深度、有效代次并清理旧代次。
- 已发布 run_id 的崩溃恢复不再重复插入同一快照。

## 合同询价与显示

- 按合同 ID 查询仅将 `is_included=true`（收到）计入估值；`is_included=false`（支付）独立返回 `payment_items`。
- 只有支付物品而没有收到物品时返回 422，不能当成免费获得这些物品。超过 500 种也明确拒绝，不截断后给出不完整估值。
- 同名多个 ID 返回 409 及候选 ID/中文/英文名称，不能 Map 后写覆盖。用户可把品目名称改为物品 ID 或唯一英文名，原有 Tab 数量格式不变。
- 纯 PLEX 六件套显示 PLEX/套；不把 `unit_price=null` 当 0，不计算 ISK/LP，原始付款方式和 PLEX 数量保留。
- ISK+物品以及 PLEX+ISK 的脑插合同过滤规则不变。
- 合同缓存使用人工空间站映射作显示名，过滤已经到期的匹配结果，采集时间使用实际缓存发布时间。
- 体积仍缺失时显示“已知体积合计 / 缺少 N 项体积，合计不完整”；明确 0 的记录正常合计，船按装箱体积乘数量。
