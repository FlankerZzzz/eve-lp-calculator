# V2 同步配置与人工维护

## 本轮范围

只维护 V2 数据库；V2.0.0 正式运行不依赖旧库，旧库仅离线归档。定时、请求池、市场估值、利润、排行榜去重公式不变。新增入口需要现有同步管理口令，空配置仍不要求口令；浏览器不保存长期凭据。

## 可视化计划

- 每个任务可切换“可视化配置 / Cron 模式”，支持每 N 分钟、每 N 小时、每天、每周。
- 最终只保存一份 Cron，时区为 Asia/Shanghai；自动开关独立，关闭自动仍可手动运行。
- 分钟间隔每个整点重新计数；小时间隔每天零点重新计数。可视化采用标准 Cron 的时间边界，不是从点击时刻起的连续间隔。
- 如 `0 9,15,18,21 * * *` 等复杂表达式保留 Cron 模式，不自动丢失多个运行时刻。主动“新建可视化计划”并保存才会替换。
- 模式属于编辑器显示状态，不产生第二份调度配置；复杂计划仍可直接使用 Cron。

## LP 分类、人工屏蔽和范围规则

`lp_exchange` 新增 `manual_blocked`、`is_guard`、`is_invalid`，取值 Y/N；保留 `is_high_sec` 与 `is_blocked`。后者成为最终生效屏蔽值，业务入口仍使用它。

- `is_guard` 初始为四个阵营战争军团（原高安过滤名单中的四个军团）；不是四个涂装军团。
- `is_invalid` 初始为原无效势力、四个涂装专属军团，以及 AK 成本大于零的方案。名单仅从原 `lib/data-policy.ts` 种子生成一次，随后以数据库配置为准。
- “屏蔽卫队产品”默认关闭，“屏蔽无效产品”默认打开；上线不改变当前有效展示范围。
- 最终屏蔽 = 单方案人工屏蔽 OR 匹配的启用屏蔽规则 OR 开启的卫队分类屏蔽 OR 开启的无效分类屏蔽。设置某条规则 N 或移除它，仅撤销该项影响，不撤销其他屏蔽。
- 分类规则按势力、军团、物品、单方案从宽到窄覆盖。不同军团的相同物品仍可具有不同分类；物品范围规则是管理员明确选择的跨军团设置。
- 原 `is_blocked` 一次性拆分：原默认排除记为分类来源，其他已屏蔽记录记为人工来源；已解除原默认排除的方案转成单方案无效分类 N，保持原有效可见性。旧系统未记录来源，无法识别“恰好与默认排除相同”的历史人工设置；此类视为原默认分类，今后新人工操作则有明确来源。
- 规则保存在现有 `runtime_state` 的 `lp_policy_config` JSON 中，不增加永久业务表。记录范围、目标 ID、字段、Y/N、原因、更新时间，并有配置版本，最多 5000 条。
- 页面提供搜索势力/军团/物品、选择目标、原因编辑、筛选配置、移除、影响预览和确认提交。查询不会应用草稿；保存检查版本，防止覆盖另一人的修改。
- 配置记录显示中文名称、范围和 ID。规则本身支持 JSON 导出/导入：最多 5 MiB，导入只载入草稿，仍须服务端校验、影响预览和确认提交；导出包含当前未提交草稿。
- Catalog 新方案与已有方案均读取持久规则；已有人工屏蔽、高安和单方案分类保留。范围规则因此也覆盖未来新出现的方案。
- `is_blocked` 物化供公开选项、详情、旧快照防漏、排行榜写入、脑插及蓝图合同关联共用。修改后排行榜排队重算；原始物品、订单、合同、历史不删除，不停止全量采集。
- 原单方案维护保留，并显示人工屏蔽、卫队、无效和最终屏蔽，避免把分类开关和人工开关混淆。

## 导出与修复导入

| 模块 | 导出内容 | 修复导入 |
| --- | --- | --- |
| 物品 | items / recipes / recipe_materials | 允许 |
| LP | lp_exchange / lp_requirements | 允许 |
| 历史 | history | 允许 |
| 订单 | 当前已发布 generation 的 orders | 禁止 |
| 合同 | contracts / contract_items，全量原始 JSON 保留 | 禁止 |
| 排行 | ranking_cache，派生缓存 | 禁止 |

脑插套装和空间站映射属于先前约定的自维护资料，不在本轮导入范围。LP 规则直接在页面维护。本轮入口是 V2 修复包，不把 CCP SDE ZIP 当作修复包；SDE 原版仍沿用专用导入流程。

### 文件格式与导出

文件为 UTF-8 JSONL，第一行为 `{ "format": "eve-v2-maintenance", "version": 1, "module": "items" }` 等格式说明，其后每行为 `{ "table": "items", "row": { ...完整原始字段... } }`。

先导出再编辑；不能执行 SQL，不接受未知列，不接受缺少字段的部分记录。数字不带单位、逗号或易读中文。LP 文件包含最终屏蔽值，但导入后仍按人工标记和当前规则重新计算，不能绕过屏蔽规则。

导出支持全部或物品 ID，历史可增加日期范围；合同按某物品筛选时保留该合同的全部明细。物品包按制造关系带上相关蓝图和材料资料。原始订单/合同嵌套字段原封不动留在 `raw_json`。

导出在只读事务中逐批输出 JSONL，浏览器原生附件下载，不建立全量 JS Blob。管理口令仅放在 POST 请求体，不放 URL、不写日志。下载期间保持一致的数据库快照，取消或完成释放连接。

### 导入流程与限制

1. 每批最多 20 MiB、10000 条；大范围修改按物品或日期范围拆分。导入先在隔离文件中暂存，不能上传整个多年历史后一次巨大事务覆盖。
2. 校验格式、模块、字段类型、Y/N、数值、主键重复、日期、价格关系、外键、蓝图产物关联和唯一配方。坏数据完整报错，整个文件拒绝，不默默跳过。
3. 预览新增、更新、不变、保护跳过及前 10 条示例；预览 30 分钟有效，尚未更改在线业务数据。预览 ID 是随机值，但访问仍要求管理口令。
4. 全部同步任务必须空闲才能预览和提交。正式提交在事务锁内再次检查任务状态、受影响记录的前值及 LP 配置版本，任何变化要求重新预览。
5. 提交前为增改记录保存原始前值和新增主键清单，备份失败则不写库；备份位于 V2 持久化目录的 `maintenance/backup-*.jsonl`。备份不属于一周同步日志，不自动删除；需要恢复时由管理员先核对范围，不提供一键破坏性回滚。
6. 按主键合并，不删除文件中没有的记录。物品 → 配方 → 材料，LP 方案 → 需求材料顺序发布，单批为一个事务，失败回滚。
7. 已保护记录永远跳过，包括其材料；可为本次新增/更新的主记录设置保护 Y，后续同步遵守保护。仅改材料若需长期保护，须同时在包中维护父方案或父蓝图的保护字段；材料不新增独立保护列。
8. 导入后排行榜排队更新。LP 分类变化作为单方案分类规则保留到后续同步；记录维护日志，不记录口令。预览隔离文件超时一天清理，备份不自动清理。

### 当前边界

不提供任意数据库文件/SQL 导入，不提供订单/合同导入，不整表替换，不自动删除历史数据，不开放旧库写入。批量上限用于保障短事务；大规模历史重建继续用后台同步作业。原版 SDE 的 URL/ZIP 页面上传不是本轮 JSONL 修复入口。
